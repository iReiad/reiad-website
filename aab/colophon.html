How this site is built, and why.

Every technical decision here, written down, including the ones that cost something. If you're building a personal site, take whatever's useful; if you're hiring me, this is roughly how I think about a problem when nobody's watching.

0build steps: the files you edit are the files that ship
0runtime dependencies, npm packages or frameworks
0tracking scripts, cookie banners or third-party analytics
1stylesheet, in nine cascade layers
1database: SQLite at the edge, no ORM
The stack, such as it is
HTML, by hand No framework, no templating, no generator. Every page is a file you can open and read. The cost is honest: shared chrome is duplicated across pages, so a header change is a scripted edit rather than one file. In exchange nothing between me and the browser can break, and the site will still work in ten years without a dependency update.
CSS, in layers @layer tokens, base, layout, components, menu, tools, article, studio, utilities, so a utility always beats a component and specificity never has to be argued about. Native nesting, no preprocessor.
Colour in oklch() Perceptually even, so "the same green, 20% lighter" is a believable statement. Two hue variables move the entire palette, and light-dark() means light and dark are one set of tokens rather than two stylesheets drifting apart.
JavaScript, as modules ES modules over the network, no bundler. The menu, the Ctrl+K palette and the shortcuts sheet are built at runtime, so a page written before they existed still gets them. Everything degrades: with JS off you lose the menu overlay and the calculators, and keep every word.
Fonts Spectral for headlines, IBM Plex Sans for text, IBM Plex Mono for data labels, Noto Sans/Serif Bengali for Bangla. Loaded from Google Fonts with display=swap, the one third-party dependency on the site, and the obvious thing to self-host next.
The dynamic half Cloudflare Pages Functions over a D1 (SQLite) database, holding articles, reader questions, subscribers, enquiries and view counts. Every endpoint checks whether the database is bound and falls back to the static behaviour if it isn't, so there is one site, not two and it degrades instead of breaking. Migrations run themselves on first request.
Auth, properly The Studio's login is now checked on the server: PBKDF2-SHA256 at 210,000 iterations, constant-time comparison, a session token stored only as a hash, and an HttpOnly cookie the page's own JavaScript cannot read. The earlier browser-side version was honest about being a lock on a glass house; this one isn't a compromise.
Hosting Static files on Cloudflare Pages, with one Pages Function (/api/news) that fetches RSS server-side, scores headlines for relevance and caches the result at the edge for half an hour.
Platform features doing real work
Layout

Container queries

Cards size to their own box rather than the window, so the same component looks right in a wide bento cell and in a narrow sidebar without a breakpoint written for each case.

Motion

Scroll-driven animations

Cards fade up as they enter the viewport and the article progress bar fills as you read, both pure CSS, driven by animation-timeline. No observers, no scroll listeners, nothing running on the main thread.

Dialogs

<dialog> and @starting-style

The menu, the palette and the shortcuts sheet are real modal dialogs, focus trapping and Escape come free, animated in and out using transition-behavior: allow-discrete.

Navigation

View transitions + speculation rules

Pages cross-fade instead of flashing white, and links prerender on hover, so most navigations are already finished when you click.

Offline

A conservative service worker

Network-first for pages so you never read a stale article, stale-while-revalidate for CSS and JS, cache-first for fonts and images. The news feed is never cached.

Typography

text-wrap and the small things

balance on headings so they never leave one word stranded, pretty on body text, tabular numerals everywhere a figure changes as you drag a slider.

Things I decided not to do
Analytics that can't identify anyone

The site counts page views, and that is the entire record: a path, a date and a number. No cookie, no visitor ID, no fingerprint, no third party, nothing that could be tied back to a person even if someone wanted to. I need to know which explainers land; I don't need to know who you are, and the difference is worth building for. The only things kept in your browser are your theme choice, which Learn terms you've read, and which articles you've reacted to: all on your device, none of it sent anywhere.

An email list, on strict terms

There is one now, and it earns its keep only if it stays honest: confirmed opt-in, so an address does nothing until you click a link; no open tracking and no click tracking, so I can't tell whether you read anything; one-click unsubscribe that works immediately and doesn't ask why. The RSS feed is still there and still better if you use a reader; it doesn't require giving me anything at all.

No build step

A generator would deduplicate the page chrome, and one day it probably should. But a build step is a thing that rots: it needs a node version, a lockfile, and an afternoon every year. For a site this size, a scripted find-and-replace across the HTML costs less over a decade.

No JavaScript framework

The interactive parts are a menu, a search palette, 5 calculators and a paste-to-publish editor. None of that needs a virtual DOM. What it does need is to still run in five years, which favours the platform over a library.

The Studio's gate isn't a vault

The publishing tool at /studio/ asks for a passkey or a passphrase, and the passphrase is checked against a PBKDF2 hash with 600,000 iterations. But a static site has no server, so that check happens in the visitor's browser: it keeps the tool private from anyone who wanders in, and it isn't cryptographic protection of anything secret. Saying so plainly seems better than implying otherwise.

Accessibility & performance notes
  • Every animation on the site stops under prefers-reduced-motion, including the ticker and the page transitions
  • Colour choices are checked against WCAG contrast in both themes; the theme follows your OS until you override it
  • Skip links on every page, real focus outlines, and dialogs that return focus where they found it
  • The Bangla pages set lang="bn" so screen readers pronounce them correctly
  • No layout shift: images carry width and height, and the fonts swap rather than block
  • No content-visibility on sections: it skips layout for offscreen content, which makes the page height a guess and the scrollbar lurch. Tried it, measured it, removed it
  • The whole site is a handful of text files: a page weighs less than a single stock photo would
